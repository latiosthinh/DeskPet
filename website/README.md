# DeskPet website

The pet website: a gallery of every pet, a page per pet with GIFs of its tricks, one-click
downloads of `<id>.deskpet` modules, a donation QR code, and per-pet counters.

Static Astro output hosted on **Cloudflare Pages**, with the existing **Pages Functions + D1**
counters. The site is generated from `pets.json` and the GIFs/modules that
`target\release\petshot.exe site` writes before a deploy.

## One-command build

From `website/`:

```powershell
npm ci
npm run build
```

`npm run build` runs `scripts/prepare-assets.mjs` and then `astro build`:

1. Reads `pets.json` and keeps every real GIF in `public/pets/<id>/`.
2. Writes a still `.png` poster next to each GIF (first frame), a 1200×630 `og.png` per pet and a
   home `og-default.png`. It also records true pixel sizes and GIF loop durations.
3. If a GIF is missing (fresh checkout, CI), writes a small **build-only fallback** GIF and a
   `FALLBACK-ART.txt` marker. Real media is never replaced; run petshot for the real art.
4. Rebuilds `src/data/pets.generated.json` from the result.
5. Astro writes the deployable site to `dist/`.

## Local development

```powershell
cd website
npm run dev            # Astro dev server, static pages only
```

To exercise the real Pages Functions and counters locally:

```powershell
npm run build
npx wrangler d1 execute deskpet --local --file=schema.sql
npx wrangler pages dev dist --d1 DB --binding STATS_TOKEN=local-dev-token
```

Open http://localhost:8788. Local D1 data lives in `website/.wrangler/` (git-ignored). The token
above is a throwaway local value; the deployed token is a Pages secret and is never committed.
`scripts/serve-for-tests.mjs` starts the same runtime for Playwright.

- Stats: http://localhost:8788/stats?token=local-dev-token
- Download: http://localhost:8788/download/ember (counted) vs
  http://localhost:8788/files/ember.deskpet (404)

## Tests and QA

```powershell
npm run lint             # oxlint
npm run format:check     # oxfmt --check + prettier --check "src/**/*.astro"
npm run test:unit        # prepare-assets + Vitest
npx playwright install chromium
npm run test:e2e         # axe, responsive/screenshots, behavior, reduced motion
npm run backend          # wrangler pages dev + local D1 endpoint checks
npm run qa:lighthouse    # mobile Lighthouse, home + /pets/ember/
npm run qa               # build + unit + e2e + backend + Lighthouse
```

What the automated checks cover:

- **axe-core (WCAG 2.2 A/AA):** home, built-in pet, add-on pet, contribute and 404, in light and dark.
- **Responsive/screenshots:** 375 px and 1440 px, both themes, every page type, no horizontal
  overflow; screenshots in `qa/screenshots/`. A 320–1920 px overflow check runs too.
- **Behavior:** gallery/navigation, download targets, OS links (`.dmg`/`.zip` → latest release),
  exactly one `POST /api/visit/<id>` per pet page load, theme persistence, system-dark fallback when
  storage is blocked, per-image pause, hero autoplay, whole-image trick frames, inline
  text spacing, and reduced-motion stills (no GIF fetch until Play).
- **SEO:** `/sitemap.xml` is a valid sitemap with home, contribute and every pet; `robots.txt` points
  at it.
- **Backend:** `/api/update/<id>`, `/api/visit/<id>`, `/download/<id>`, `/files/*.deskpet` 404,
  `/stats` token gate, and D1 counter deltas. `/download` bytes are compared with the module on disk.
  A missing add-on module gets a test-only fixture for the duration of the run; a real module is
  never edited or deleted. `STATS_TOKEN` is taken from `process.env` or a test-only default; no real
  secret is read or written.
- **Lighthouse (mobile, default throttling):** Performance ≥ 95, Accessibility / Best Practices /
  SEO = 100, CLS < 0.05 on `/` and `/pets/ember/`. HTML/JSON reports in `qa/lighthouse/`.

`website/qa/`, `test-results/`, `playwright-report/` and `dist/` are git-ignored.

## Petshot (before a deploy)

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File windows\check-pet.ps1
target\release\petshot.exe site build\pets website
cd website
npm run build
```

`petshot site` writes each pet's GIFs into `public/pets/<id>/`, each add-on module into
`public/files/`, and rewrites `pets.json` (names, descriptions, versions, trick ids, file sizes).
`npm run build` then derives posters/OG images and true durations. `public/*` stays git-ignored
except the committed donation card (`donate-qr.png` and `donate-qr.webp`).

## Backend contract (unchanged)

| Route | Behaviour |
| --- | --- |
| `GET /api/update/<id>` | `{"version":"<semver>"}`, counted as `update`; unknown → 404 |
| `GET /download/<id>` | module bytes + attachment filename, counted as `download`; built-in/unknown → 404 |
| `POST /api/visit/<id>` | 204, counted as `visit`; unknown → 404 |
| `GET /files/*.deskpet` | always 404 (downloads must go through `/download/<id>`) |
| `GET /stats?token=...` | counts page behind `STATS_TOKEN`; missing/wrong token → 404 |

Counts are one row per pet, kind and UTC day; each event is an upsert `n = n + 1`.

## Deploying (owner, not CI)

One-time setup from `website/`:

```powershell
npx wrangler login
npx wrangler d1 create deskpet
```

Copy the printed `database_id` into `wrangler.toml`, then:

```powershell
npx wrangler d1 execute deskpet --remote --file=schema.sql
npx wrangler pages project create deskpet --production-branch main
npx wrangler pages secret put STATS_TOKEN --project-name deskpet
```

The real donation card (`public/donate-qr.png` and `public/donate-qr.webp`) is committed; the build
fails if either is missing or their dimensions differ.

Before each deploy, from the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File windows\check-pet.ps1
target\release\petshot.exe site build\pets website
cd website
npm run build
npx wrangler pages deploy
```

`wrangler.toml` sets `pages_build_output_dir = "dist"`, so the deploy command is the same as
before; functions and the D1 binding are unchanged. Nothing in this repository deploys
automatically, and CI has no deploy step and no secrets.

The app's **Get More Pets…** and update check use `https://deskpet.pages.dev`. If the project
gets another address, change `site()` in `windows/src/net.rs` before releasing the app.
